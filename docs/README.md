# 문서 관리

| 위치 | 목적 | 작성·갱신 |
|---|---|---|
| progress.md | 전체 진행·다음 작업·막힌 점 요약 | 통합 담당, 각자 PR 보고를 바탕으로 갱신 |
| devlogs/이름/ | 개발·검증·협업 요청 기록 | 본인, 작업 종료 시 |
| meetings/ | 실제 회의 내용 | 회의 작성자, 날짜별 파일 |
| prototype-review.md | 동일 기준 비교·선정 이유 | 전체 비교 후 통합 담당 정리 |
| decisions.md | 합의한 운영·방향 기록 | 결정 발생 시 |
| submissions/ | 계획서·1차·최종 발표 제출본 | 담당 배정 후 |

일정·진행 상태는 progress.md, 상세 근거는 개인 로그, 할 일·담당·완료 기준은 GitHub Issues에 기록합니다.
아직 GitHub 이슈나 PR은 생성하지 않았습니다.
회의록에는 실제 참석·논의·합의만 적습니다. AI 제안을 팀 결정으로 기록하지 않습니다.
개발 구조·API 설계·DB 스키마·설치 프로필은 공통 틀에 넣지 않습니다. 각 브랜치 development/에서 관리합니다.
