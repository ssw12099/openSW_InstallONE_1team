## 확인한 결과
- 환경 (모두 실제 장비, 모의 좌석 아님)
  - PC: Windows 11 Home 25H2 (26200.9974), i7-12700KF 20스레드, RAM 32GB, NVMe SSD
  - VM 프로그램: VirtualBox 7.2.22 (Home이라 Hyper-V 관리자 없음)
  - VM: Windows 11 Enterprise 평가판 26H2 (26300.9457, 한국어), RAM 8GB, 디스크 80GB, EFI·보안 부팅·TPM 2.0, 어댑터 1 NAT + 어댑터 2 호스트 전용, 로컬 관리자 `labadmin`
  - WSL: WSL 3.0.5, Ubuntu 26.04.1 LTS, Python 3.14.4, ansible 15.0.0 (ansible-core 2.22.0), ansible-runner 2.4.3, pywinrm 0.5.0
- 실행 방법: VM_TEST.md 3~5번을 문서에 적힌 명령 그대로 실행 (3번 WinRM 3줄은 VM 안 관리자 PowerShell)
- 실제 결과 및 근거
  - WinRM 3줄 실행 후 VM 안 점검: WinRM 서비스 Running/Automatic, HTTP 리스너 5985, 방화벽 규칙 `InstallONE-WinRM-HTTP`(Profile Any, Allow), `LocalAccountTokenFilterPolicy=1`, community.chocolatey.org:443 접속됨
  - PC(Windows) → VM 5985 TCP 열림. 인증 없이 `POST /wsman` → `401`, `WWW-Authenticate: Negotiate` (NTLM으로 접속할 수 있는 상태)
  - WSL2를 켠 뒤 VirtualBox가 Hyper-V 위에서 실행됨 (VBox.log `HM: HMR3Init: Attempting fall back to NEM: VT-x is not available`)
    - CPU 4개: 바탕 화면까지 부팅한 뒤 `AHCI#0: Port 0 reset` 3번(52초, 1분 34초, 2분 4초) → 화면·키보드 멈춤, 5985 응답 없음
    - CPU 2개 (반가상화 Minimal, 호스트 I/O 캐시 켬): 펌웨어 `DXE_AP` 단계에서 멈춤 (7분 동안 화면 없음)
    - CPU 1개 (나머지 같음): VM 시작 3분 40초 뒤 5985 열림, 디스크 리셋 0번 → 이 설정으로 '깨끗한 상태' 스냅샷
  - 4~5번: `wsl --install -d Ubuntu`, apt, `git clone`, 가상환경, `pip install -r requirements.txt -r requirements-ansible.txt` 모두 오류 없이 끝남
- 미확인 부분 (실제 VM 기준, 아직 안 함): WSL에서 VM으로 포트 확인, win_ping, 서버로 실제 설치·검증("1번 PC에 Python 실습환경 설치해 줘"), 이미 설치됨, 연결 실패

## 막힌 점·협업 요청
- 문제와 해결
  - Windows 설치가 2시간 넘게 멈췄다가 "Windows 11을 설치하지 못했습니다": VM 디스크에 켜 둔 discard(TRIM) 때문에 디스크 요청이 끝나지 않음 (로그에 남은 취소 요청 29,659건 중 TRIM 19,161건, `AHCI#0: Port 0 reset` 반복). discard를 끈 새 디스크로 다시 설치해서 해결
  - WSL2를 켠 뒤 VM 멈춤: 위 결과대로 VM CPU 1개로 해결 (느리지만 동작)
  - Windows 첫 설정의 Microsoft 계정 화면: '로그인 옵션 → 대신 도메인 가입'으로 로컬 계정
  - 재부팅 뒤 Ubuntu가 설치돼 있지 않음: `wsl --install -d Ubuntu` 한 번 더
- 누구에게 무엇이 필요한지
  - 소선웅: VirtualBox VM과 WSL2를 같은 PC에서 쓰면 VM CPU를 1개로 (또는 Windows 설치를 WSL2 켜기 전에). VM_TEST.md 2번 주의, 11번 참고
